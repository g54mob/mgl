## 1. What Is Feel?

**Feel** is a **game juice / feedback framework**. It lets you orchestrate visual, audio, and haptic effects that fire in response to game events — like camera shakes on explosion, screen flash on damage, scale bounce on pickup, haptic vibration on mobile tap, etc.

Instead of writing custom coroutines for every effect, you **compose feedback sequences** using a visual inspector (the MMF_Player), then trigger them with a single line of code.

## 4. Installation & Setup

### 4.1 Import

1. Import the Feel `.unitypackage` into your project
2. Three folders appear: `MMFeedbacks/`, `MMTools/`, `NiceVibrations/`

### 4.2 Assembly Definitions

Feel uses assembly definitions (`.asmdef` / `.asmref`). If your scripts need to reference Feel classes, either:
- Add `MoreMountains.Feedbacks` and `MoreMountains.Tools` to your assembly definition references
- Or place your scripts outside of any assembly definition

### 4.3 No Special Scene Setup Required

Unlike Highlight Plus, Feel doesn't need a renderer feature. Just:
1. Create a GameObject
2. Add `MMF_Player` component
3. Add feedbacks to it
4. Trigger via code or inspector

## 5. Core Concept: MMF_Player + Feedbacks

### 5.1 The Mental Model

```
Game Event (e.g., "player got hit")
    ↓
Your Script calls: myFeedbackPlayer.PlayFeedbacks()
    ↓
MMF_Player iterates through its feedback list
    ↓
Each MMF_Feedback executes:
  → Camera Shake feedback broadcasts shake event
  → Flash feedback broadcasts flash event
  → Scale feedback tweens object scale
  → Sound feedback plays audio clip
    ↓
Shakers on target objects receive events and shake
```

### 5.2 MMF_Player

The **container component** that holds a list of feedbacks.

**Key Properties:**

| Property | Type | Purpose |
|---|---|---|
| `FeedbacksList` | List<MMF_Feedback> | All feedbacks in this player |
| `InitializationMode` | enum | `Awake`, `Start`, or `Script` |
| `AutoPlayOnStart` | bool | Play immediately on Start |
| `AutoPlayOnEnable` | bool | Play every time GameObject enables |
| `Direction` | enum | `TopToBottom` or `BottomToTop` |
| `DurationMultiplier` | float | Scale all durations |
| `PerformanceMode` | bool | Skip inspector refresh during play |
| `PlayCount` | int | How many times this player has played |

**Direction Modes:**
- `TopToBottom`: feedbacks play in list order
- `BottomToTop`: feedbacks play in reverse

### 5.3 MMF_Feedback (Base Class)

Every feedback type inherits from `MMF_Feedback`. Common properties:

| Property | Type | Purpose |
|---|---|---|
| `Active` | bool | Enable/disable this feedback |
| `Label` | string | Custom display name |
| `Timing` | MMFeedbackTiming | Delay, repeat, duration |
| `Chance` | float | 0–100% probability of firing |
| `Channel` | int | Which channel to broadcast on |
| `MMChannelDefinition` | MMChannel | ScriptableObject channel (alternative to int) |
| `UseRange` | bool | Only affect shakers within distance |
| `RangeDistance` | float | Max range |
| `RandomizeOutput` | bool | Randomize intensity each play |

### 5.4 Timing (MMFeedbackTiming)

Every feedback has a Timing section:

| Property | Purpose |
|---|---|
| `InitialDelay` | Wait before starting |
| `CooldownDuration` | Min time between triggers |
| `RepeatForever` | Loop forever |
| `NumberOfRepeats` | Loop N times |
| `DelayBetweenRepeats` | Wait between loops |
| `Quantized` | Snap to beat (for music sync) |

## 7. Scene Setup — Step by Step

### 7.1 Basic: Camera Shake on Button Press

1. Create empty GameObject → name it "DamageFeedback"
2. Add Component → `MMF Player`
3. In the Inspector, click **"Add new feedback"** dropdown
4. Select **Camera → Camera Shake**
5. Configure: `ShakeDuration = 0.3`, `ShakeAmplitude = 2`, `ShakeFrequency = 20`
6. **On your Camera:** Add Component → `MMCameraShaker`
   - This is the **shaker** — it receives the shake event
7. In your script:

```csharp
using MoreMountains.Feedbacks;

public class DamageHandler : MonoBehaviour
{
    [SerializeField] MMF_Player damageFeedback;
    
    public void OnTakeDamage()
    {
        damageFeedback.PlayFeedbacks();
    }
}
```

8. Wire the `DamageFeedback` player into the `damageFeedback` field
9. Press Play → call `OnTakeDamage()` → camera shakes!

### 7.2 Scale Punch on Pickup

1. Create MMF_Player on the pickup object
2. Add feedback: **Transform → Scale**
3. Set `AnimateScaleX/Y/Z` curves to a "punch" shape (scale up then back to 1)
4. Set `AnimateScaleDuration = 0.3f`
5. Set target to the pickup object itself
6. Call `PlayFeedbacks()` on pickup

### 7.3 Screen Flash on Damage

1. Create a **full-screen UI Image** (Canvas → Image, stretch to fill)
2. Set Image color to transparent
3. Add `MMFlash` component to the Image
4. Create MMF_Player on your damage handler
5. Add feedback: **Camera → Flash**
6. Set `FlashColor`, `FlashDuration`, `FlashAlpha`
7. Call `PlayFeedbacks()`

### 7.4 Freeze Frame (Hit Stop)

1. Create MMF_Player
2. Add feedback: **Time → Freeze Frame**
3. Set `FreezeFrameDuration = 0.05f` (50ms)
4. Trigger on enemy hit

### 7.5 Combining Multiple Feedbacks

One MMF_Player can hold **many feedbacks** that all play together:

```
MMF_Player "OnEnemyDeath":
  1. MMF_CameraShake        → shake camera
  2. MMF_FreezeFrame         → 50ms hit stop
  3. MMF_Flash               → white flash
  4. MMF_ParticlesInstantiation → spawn explosion VFX
  5. MMF_Scale               → enemy squash
  6. MMF_Destroy             → destroy enemy (with delay)
```

Use `Timing.InitialDelay` to stagger effects.

## 8. Shakers (Receiving End)

Shakers are **receiver components** that listen for events broadcast by feedbacks.

### How Shakers Work

```
MMF_CameraShake (feedback) → broadcasts "CameraShakeEvent" on channel 0
    ↓
MMCameraShaker (on camera) → listens for "CameraShakeEvent" on channel 0
    ↓
Camera shakes!
```

### Available Shakers

| Shaker Component | Paired With Feedback | What It Shakes |
|---|---|---|
| `MMCameraShaker` | `MMF_CameraShake` | Camera position/rotation |
| `MMCameraZoom` | `MMF_CameraZoom` | Camera FOV |
| `MMFlash` | `MMF_Flash` | Full-screen flash Image |
| `MMPositionShaker` | `MMF_PositionShake` | Transform position |
| `MMRotationShaker` | `MMF_RotationShake` | Transform rotation |
| `MMScaleShaker` | `MMF_ScaleShake` | Transform scale |
| `MMLightShaker` | `MMF_Light` | Light properties |
| `MMAudioSourcePitchShaker` | `MMF_AudioSourcePitch` | Audio pitch |
| `MMAudioSourceVolumeShaker` | `MMF_AudioSourceVolume` | Audio volume |
| `MMBlink` | `MMF_Flicker` | Object blinking |
| `MMWiggle` | `MMF_Wiggle` | Continuous wiggle |

### Channel Matching

Shakers only respond to feedbacks on the **same channel**:
- Feedback `Channel = 0` → Shaker `Channel = 0` ✅
- Feedback `Channel = 0` → Shaker `Channel = 1` ❌

Use `MMChannel` ScriptableObjects for cleaner channel management.

## 9. Springs System

Springs provide physics-based bouncy motion. More natural than curve-based animation.

### Key Spring Components

Located in `MMFeedbacks/Springs/`:

- `MMSpringPosition` — spring on position
- `MMSpringRotation` — spring on rotation
- `MMSpringScale` — spring on scale
- `MMSpringColor` — spring on color
- `MMSpringFloat` — spring on any float
- `MMSpringTextureOffset` / `MMSpringTextureScale` — spring on material properties

### Spring Feedbacks

- `MMF_PositionSpring`
- `MMF_RotationSpring`
- `MMF_ScaleSpring`
- `MMF_SquashAndStretchSpring`

### Spring Parameters

| Parameter | Purpose |
|---|---|
| `Damping` | How quickly oscillation dies (0 = never, 1 = instant) |
| `Frequency` | Speed of oscillation |
| `BumpAmount` | Initial displacement on trigger |

## 11. Nice Vibrations (Mobile Haptics)

### 11.1 What Is It?

Nice Vibrations lets you play **haptic feedback** on iOS (Taptic Engine) and Android devices, plus gamepad rumble on consoles/PC.

### 11.2 Key Classes

| Class | Purpose |
|---|---|
| `HapticPatterns` | Static methods for quick haptic playback |
| `HapticController` | Low-level haptic control |
| `HapticSource` | MonoBehaviour for inspector-driven haptics |
| `HapticReceiver` | Receives haptic events |
| `HapticClip` | ScriptableObject holding haptic data |

### 11.3 Preset Haptics (Simplest API)

```csharp
using Lofelt.NiceVibrations;

// Play a preset haptic
HapticPatterns.PlayPreset(HapticPatterns.PresetType.Selection);    // Light tap
HapticPatterns.PlayPreset(HapticPatterns.PresetType.Success);      // Success feel
HapticPatterns.PlayPreset(HapticPatterns.PresetType.Warning);      // Warning buzz
HapticPatterns.PlayPreset(HapticPatterns.PresetType.Failure);      // Error rumble
HapticPatterns.PlayPreset(HapticPatterns.PresetType.LightImpact);  // Light thump
HapticPatterns.PlayPreset(HapticPatterns.PresetType.MediumImpact); // Medium thump
HapticPatterns.PlayPreset(HapticPatterns.PresetType.HeavyImpact);  // Heavy thump
HapticPatterns.PlayPreset(HapticPatterns.PresetType.RigidImpact);  // Hard impact
HapticPatterns.PlayPreset(HapticPatterns.PresetType.SoftImpact);   // Soft impact
```

### 11.4 Available Presets

| Preset | Feel | Best For |
|---|---|---|
| `Selection` | Very light tap | UI selection, menu navigation |
| `Success` | Satisfying double-buzz | Task complete, achievement |
| `Warning` | Alert buzz | Low health, timer warning |
| `Failure` | Error rumble | Death, failed action |
| `LightImpact` | Light thump | Small collision, footstep |
| `MediumImpact` | Medium thump | Weapon hit, jump land |
| `HeavyImpact` | Heavy thump | Explosion, big hit |
| `RigidImpact` | Sharp hard tap | Metal collision |
| `SoftImpact` | Dull soft tap | Soft landing |

### 11.5 Custom Haptics with HapticClip

1. Create a `.haptic` file (exported from Lofelt Studio or designed manually)
2. Create `HapticClip` asset: Right-click → Create → Nice Vibrations → Haptic Clip
3. Assign the `.haptic` file to the clip
4. Play via code:

```csharp
HapticController.Load(myHapticClip.json);
HapticController.Play();
```

### 11.6 MonoBehaviour API (HapticSource)

1. Add `HapticSource` component to a GameObject
2. Assign a `HapticClip`
3. Call `Play()` from code or UnityEvent

```csharp
HapticSource source = GetComponent<HapticSource>();
source.Play();
source.Stop();
```

### 11.7 Haptic Samples

The package includes pre-made haptic clips in `HapticSamples/` for common game effects — collision, UI, notification, etc.

## 12. C# API Reference

### 12.1 MMF_Player

```csharp
using MoreMountains.Feedbacks;

MMF_Player player = GetComponent<MMF_Player>();

// Play all feedbacks
player.PlayFeedbacks();

// Play with a specific position (for range-based feedbacks)
player.PlayFeedbacks(transform.position);

// Play with intensity multiplier
player.PlayFeedbacks(transform.position, feedbacksIntensity: 0.5f);

// Stop all feedbacks
player.StopFeedbacks();

// Pause / Resume
player.PauseFeedbacks();
player.ResumeFeedbacks();

// Reset
player.ResetFeedbacks();

// Restore initial values (undo all changes feedbacks made)
player.RestoreInitialValues();

// Skip to the end (instant completion)
player.SkipToTheEnd();

// Get total duration of all feedbacks
float duration = player.TotalDuration;

// Check if playing
bool playing = player.IsPlaying;

// Initialization
player.Initialization();
```

### 12.2 Events on MMF_Player

```csharp
// Via Inspector: MMF_Player has Events section
// OnPlay, OnPause, OnResume, OnRevert, OnComplete

// Or via the Events class:
player.Events.OnPlay.AddListener(() => Debug.Log("Started"));
player.Events.OnComplete.AddListener(() => Debug.Log("Done"));
```

### 12.3 Individual Feedback Control

```csharp
// Get a specific feedback by label
MMF_Feedback fb = player.FeedbacksList.Find(f => f.Label == "CameraShake");
fb.Active = false; // disable it

// Get by type
MMF_Scale scaleFb = player.GetFeedbackOfType<MMF_Scale>();
```

### 12.4 Shaker Events (Manual Triggering)

```csharp
using MoreMountains.Feedbacks;

// Trigger camera shake event directly (without MMF_Player)
MMCameraShakeEvent.Trigger(
    duration: 0.5f,
    amplitude: 2f,
    frequency: 20f,
    amplitudeX: 0f, amplitudeY: 0f, amplitudeZ: 0f,
    infinite: false,
    channel: 0,
    useUnscaledTime: false
);
```

### 12.5 Nice Vibrations API

```csharp
using Lofelt.NiceVibrations;

// Quick presets
HapticPatterns.PlayPreset(HapticPatterns.PresetType.MediumImpact);

// Emphasis (custom intensity + sharpness)
HapticPatterns.PlayEmphasis(amplitude: 0.8f, frequency: 0.5f);

// Constant vibration
HapticPatterns.PlayConstant(amplitude: 0.5f, frequency: 0.3f, duration: 0.5f);

// Control
HapticController.Stop();
HapticController.clipLevel = 0.5f; // global volume
HapticController.clipFrequencyShift = 0.2f; // pitch shift

// Check support
bool supported = DeviceCapabilities.isVersionSupported;
```

## 13. Channels & Events System

### 13.1 Integer Channels

Simplest approach — just use matching integers:
- Feedback: `Channel = 0`
- Shaker: `Channel = 0`

### 13.2 MMChannel ScriptableObjects

More scalable approach:
1. Right-click → Create → More Mountains → MMChannel
2. Name it (e.g., "PlayerDamageChannel")
3. Assign to feedback: `ChannelMode = MMChannel`, `MMChannelDefinition = PlayerDamageChannel`
4. Assign same channel to the shaker

### 13.3 Range-Based Events

Feedbacks can be distance-limited:
- `UseRange = true` on the feedback
- `RangeDistance = 10f`
- Only shakers within 10 units will respond
- `RangeFalloff` curve controls intensity falloff

## 15. Performance Tips

1. **Reuse MMF_Players** — don't create new ones each frame
2. **Object pool particles** — use `MMSimpleObjectPooler` with `MMF_ParticlesInstantiation`
3. **Use `PerformanceMode = true`** in production builds
4. **Channel matching** — shakers on wrong channels still consume CPU checking
5. **Disable unused shakers** — remove shaker components you don't need
6. **Use springs over curves** for procedural feel with less configuration
7. **Nice Vibrations:** Only call on mobile builds with `#if UNITY_IOS || UNITY_ANDROID`

## 16. Troubleshooting

| Problem | Fix |
|---|---|
| Camera doesn't shake | Add `MMCameraShaker` to the Camera + match channel |
| Flash doesn't show | Add `MMFlash` to a full-screen UI Image |
| Feedback plays but nothing happens | Check if target is assigned on the feedback |
| Scale feedback doesn't reset | Enable `RestoreInitialValuesOnDisable` on player |
| Multiple cameras shake | Use different channels per camera |
| Haptics don't work | Build on real device (not editor), check `DeviceCapabilities.isVersionSupported` |
| Feedbacks play out of order | Check `Timing.InitialDelay` values and Direction mode |
| "No feedback of type X" error | Missing assembly reference to `MoreMountains.Feedbacks` |

### 18.2 Object Pooling (`MMTools/Core/MMObjectPool/`)

Pre-instantiate objects to avoid runtime Instantiate/Destroy GC spikes.

**Scene Setup:**

```csharp
    {

public class Bullet : MMPoolableObject

}
```

## 20. Deep Dive: Springs System (Physics-Based Animation)

### 20.1 How Springs Work

A spring is a physics simulation that moves a value toward a target with **overshoot and oscillation** — like a real spring bouncing.

```
                  overshoot
                    ╱╲
Target → ─────────╱──╲──────── settles at target
                       ╲╱
```

Two parameters control everything:
- **Damping** (0–1): How fast oscillation dies. Low = bouncy, High = stiff
- **Frequency** (0.1–40): How fast it oscillates. Higher = faster bounce

### 20.2 Spring Types

| Spring Type | Value Type | Use For |
|---|---|---|
| `MMSpringFloat` | float | Any single value (scale, alpha, fill) |
| `MMSpringVector2` | Vector2 | UV offsets, 2D positions |
| `MMSpringVector3` | Vector3 | 3D position, rotation, scale |
| `MMSpringVector4` | Vector4 | Advanced shader properties |
| `MMSpringColor` | Color | Color transitions |

### 20.3 All Spring Components (31 total!)

**Transform springs:**
- `MMSpringPosition` — Spring on transform.position
- `MMSpringRotation` — Spring on transform.rotation
- `MMSpringScale` — Spring on transform.localScale
- `MMSpringRotationAround` — Spring orbit around point
- `MMSpringSquashAndStretch` — Cartoon deformation

**UI springs:**
- `MMSpringImageAlpha` — Image transparency
- `MMSpringImageColor` — Image color
- `MMSpringImageFillAmount` — Image fill (health bars!)
- `MMSpringRectTransformPosition` — RectTransform position
- `MMSpringRectTransformSizeDelta` — RectTransform size

**TMP springs:**
- `MMSpringTMPAlpha` — Text alpha
- `MMSpringTMPTextColor` — Text color
- `MMSpringTMPFontSize` — Text size
- `MMSpringTMPCharacterSpacing` — Letter spacing
- `MMSpringTMPLineSpacing` — Line spacing
- `MMSpringTMPWordSpacing` — Word spacing
- `MMSpringTMPDilate` — Text dilation
- `MMSpringTMPSoftness` — Text softness

**Audio springs:**
- `MMSpringAudioSourcePitch` — Audio pitch
- `MMSpringAudioSourceVolume` — Audio volume

**Camera springs:**
- `MMSpringCameraFieldOfView` — Camera FOV
- `MMSpringCameraOrthographicSize` — Ortho camera size

**Rendering springs:**
- `MMSpringLightColor` — Light color
- `MMSpringLightIntensity` — Light brightness
- `MMSpringLightRange` — Light range
- `MMSpringSpriteColor` — SpriteRenderer color
- `MMSpringAnimatorSpeed` — Animator speed
- `MMSpringShaderController` — Shader property
- `MMSpringTextureOffset` — Material texture offset
- `MMSpringTextureScale` — Material texture scale

**Time:**
- `MMSpringMMTimeScale` — Time.timeScale with spring feel

### 20.4 Using Springs in Code

```csharp
using MoreMountains.Feedbacks;

// Via component
MMSpringScale springScale = GetComponent<MMSpringScale>();
springScale.BumpRandom(); // random bump
springScale.MoveTo(new Vector3(1.5f, 1.5f, 1.5f)); // spring to target

// Via spring data directly
MMSpringFloat mySpring = new MMSpringFloat();
mySpring.Damping = 0.5f;
mySpring.Frequency = 6f;
mySpring.SetCurrentValueAsInitialValue();

// In Update:
mySpring.TargetValue = desiredValue;
mySpring.UpdateSpringValue(Time.deltaTime);
float animated = mySpring.CurrentValue;
```

```csharp
public class Enemy : MonoBehaviour

    [SerializeField] MMF_Player deathFeedback;

    public void TakeDamage(int amount, Vector3 hitPoint)
    {
        health -= amount;
        hitFeedback.PlayFeedbacks(hitPoint, amount / 100f);
        
        if (health <= 0)
            deathFeedback.PlayFeedbacks(transform.position);
    }
}
```

## 1. What Is Highlight Plus?

Highlight Plus is a **visual feedback system** that draws outlines, glows, overlays, see-through effects, hit flashes, target markers, and icons around 3D objects in your Unity scene. Think of it as "the glowing outline you see in every game when you hover over something you can pick up."

It works entirely through **URP Renderer Features** + **MonoBehaviour components** — no shader replacement needed on your existing materials.

---

## 2. When Would You Use It?

| Use Case | Example |
|---|---|
| **Hover highlight** | Glow around an interactable object when the mouse is over it |
| **Selection indicator** | Outline stays on a clicked object |
| **See-through walls** | X-ray silhouette of a player behind obstacles |
| **Hit feedback** | Flash overlay when an enemy takes damage |
| **Target marker** | Animated crosshair/circle on the ground below a selected unit |
| **Icon marker** | Floating 3D icon above a quest NPC |

---

## 3. Installation & URP Setup

### 3.1 Prerequisites

- Unity 2021.3 or later
- URP package installed via Package Manager

### 3.2 Step-by-Step Installation

1. **Import the package** into your Unity project (Assets → Import Package or drag `.unitypackage`).

2. **Open Project Settings → Graphics**  
   - You will see a field called **Scriptable Render Pipeline Settings** with your URP Asset assigned.

3. **Double-click the URP Asset** (e.g., `UniversalRenderPipelineAsset`).  
   - This selects it in the Inspector.

4. **Find the Renderer List** on the URP Asset.  
   - It shows one or more **Forward Renderer** assets (e.g., `UniversalRenderer`).

5. **Double-click the Forward Renderer** asset to select it.

6. **Click the "+" button** under **Renderer Features**.

7. **Select "Highlight Plus"** from the dropdown list.  
   - This adds `HighlightPlusRenderPassFeature` to the renderer.

8. **IMPORTANT:** Also check **Settings → Quality**. Each quality level can have its own URP Asset. Repeat steps 3–7 for every URP Asset referenced there.

> **Without this Renderer Feature, nothing will render!** This is the #1 setup mistake.

### 3.3 Renderer Feature Options

Once added, the Highlight Plus Renderer Feature has these settings:

| Setting | What It Does |
|---|---|
| **Show In Preview Camera** | Renders effects in Scene view preview cameras |
| **Clear Stencil** | Fixes conflicts with other stencil-based assets |

## 4. Core Concepts

### 4.1 How It Works Internally

```
Your Object (MeshRenderer)
    ↓
HighlightEffect component reads mesh data
    ↓
HighlightPlusRenderPassFeature (URP Renderer Feature)
    ↓
Custom shader passes draw outline/glow/overlay/etc.
    ↓
Final composited image on screen
```

- **No material changes** — your object's original material is untouched.
- Effects are rendered via **extra draw passes** injected by the URP Renderer Feature.
- The component caches mesh data for performance.

### 4.2 Effect Group (Who Gets Highlighted?)

The `effectGroup` property on `HighlightEffect` controls scope:

| Value | Meaning |
|---|---|
| `OnlyThisObject` | Only this exact GameObject |
| `Children` | This object + all children (default) |
| `RootToChildren` | From the topmost parent down to all children |
| `LayerInScene` | All objects in a specific layer |
| `LayerInChildren` | All children in a specific layer |
| `Scripting` | You manually assign renderers via code |

### 4.3 Visibility Modes

Many effects have a `Visibility` setting:

| Value | Meaning |
|---|---|
| `Normal` | Effect only visible when object is visible |
| `AlwaysOnTop` | Effect renders on top of everything |
| `OnlyWhenOccluded` | Effect only shows when object is behind something |

## 5. Key Components

### 5.1 `HighlightEffect` (The Main Component)

**What:** The core component you add to any GameObject to make it highlightable.  
**Location:** `Runtime/Scripts/HighlightEffect.cs` (157KB — it's big!)

**How to add:**
1. Select your GameObject in the Hierarchy
2. Inspector → Add Component → search "Highlight Effect"

**Key Inspector Sections:**

| Section | Controls |
|---|---|
| **Include** | Which objects are affected (`effectGroup`) |

| **Outline** | Edge outline around the object |
| **Outer Glow** | Soft glow emanating outward |
| **Inner Glow** | Glow on the inside edges |
| **See-Through** | X-ray silhouette behind occluders |
| **Target FX** | Animated sprite on the ground |
| **Icon FX** | 3D mesh icon floating above |
| **Hit FX** | Damage flash effect |


1. On `HighlightManager` (or `HighlightTrigger`), enable `selectOnClick`
2. Optionally assign a `selectedProfile` for a different look when selected
3. Enable `singleSelection` for one-at-a-time selection

### 7.5 See-Through Setup

1. Add `HighlightEffect` to the object you want to see through walls
2. Set `seeThrough = WhenHighlighted`
3. Add `HighlightSeeThroughOccluder` to any wall objects
4. Walls must have Colliders

### 7.6 Static Objects

Objects marked as **Static** in Unity need a **MeshCollider** (can be disabled) to be highlighted, because Unity batches their meshes.

## 11. Performance Tips

1. **Use `Fastest` or `Medium` quality** unless you need pixel-perfect outlines
2. **Increase `outlineDownsampling` / `glowDownsampling`** for cheaper effects
3. **Enable `optimizeSkinnedMesh`** for characters (reduces draw calls)
4. **Enable `GPUInstancing`** (on by default)
5. **Use `combineMeshes`** when highlighting parent+children to reduce draw calls
6. **Use profiles** — avoid per-frame property changes
7. **Set `PerformanceMode = true`** on the Highlight Manager in production
8. **Disable effects you don't use** (set intensity to 0)
9. **Use LOD-friendly approach**: disable highlight on distant objects

## 14. Real-World Example: Replacing a Custom Fresnel Highlighter

> This section shows how to migrate from a **custom URP Renderer Feature + Shader Graph fresnel approach** (as used in Phase B/D of this project) to Highlight Plus. This is the exact use case in our codebase.

### 14.1 The Problem (What Phase B Does Without Highlight Plus)

Phase B implements `FresnelHighlighter.cs` — a temporary highlighting system that:

1. **Every frame** raycasts from the camera forward
2. If the ray hits a tool → swaps the object's **layer** to a special "Highlighted" layer (31)
3. If the ray hits a grabbable → same layer swap, different color
4. A **URP Renderer Feature** (Render Objects) is configured to render layer 31 with an additive fresnel shader graph material
5. Next frame, `ClearAll()` restores original layers

**This requires:**
- A custom "Highlighted" layer in Project Settings
- A custom Shader Graph (`Highlight_Fresnel_Additive`)
- A custom material (`M_Highlight_Fresnel`)
- A URP Render Objects renderer feature configured for that layer
- Layer swapping every frame (fragile, interferes with physics layers)
- `MaterialPropertyBlock` for per-object color overrides

**Phase D extends** the same system with building/wrench highlight colors.

### 14.2 The Migration (Replace With Highlight Plus)

Highlight Plus eliminates **all** of the above complexity. No custom layers, no shader graph, no renderer feature configuration (beyond adding the Highlight Plus feature itself).

### 14.3 The Replacement Script

```csharp
using UnityEngine;
using HighlightPlus;

/// <summary>
/// I outline whatever the player looks at using Highlight Plus.
/// Every Update I raycast from the camera. If I hit a tool/grabbable/building,
/// I enable HighlightEffect on it with the appropriate color.
/// ClearAll disables the previous highlight each frame.
///
/// SETUP REQUIRED:
///   1. URP Renderer Data → Add Renderer Feature → Highlight Plus
///   2. Create HighlightProfile assets for each color preset (optional but recommended)
///   3. Assign profiles or colors in inspector
///
/// Replaces: FresnelHighlighter.cs (Phase B) + all custom layer/shader/material setup
/// </summary>
public class HighlightPlusHighlighter : MonoBehaviour
{
    [Header("Raycast")]
    [SerializeField] Camera _cam;
    [SerializeField] float _interactRange = 2f;
    [SerializeField] LayerMask _interactLayerMask;

    [Header("Highlight Colors")]
    [SerializeField] Color _toolColor = new Color(0.25f, 0.85f, 1f, 1f);
    [SerializeField] Color _grabbableColor = new Color(0.25f, 0.85f, 1f, 1f);
    // Phase D:
    // [SerializeField] Color _buildingColor = new Color(0.25f, 0.85f, 1f, 1f);
    // [SerializeField] Color _wrenchEnableColor = new Color(0.3f, 1f, 0.3f, 1f);
    // [SerializeField] Color _wrenchDisableColor = new Color(1f, 0.3f, 0.3f, 1f);

    [Header("Highlight Settings")]
    [SerializeField] float _outlineWidth = 0.5f;
    [SerializeField] float _glowIntensity = 1.5f;

    HighlightEffect currentHighlight;
    GameObject currentTarget;

    void Update()
    {
        ClearCurrent();
        OutlineLookedAtThing();
    }

    void ClearCurrent()
    {
        if (currentHighlight != null)
        {
            currentHighlight.highlighted = false;
            currentHighlight = null;
            currentTarget = null;
        }
    }

    void OutlineLookedAtThing()
    {
        if (!Physics.Raycast(_cam.transform.position, _cam.transform.forward,
            out RaycastHit hit, _interactRange, _interactLayerMask))
            return;

        // → Check for tool
        if (hit.collider.GetComponentInParent<BaseHeldTool>() != null)
        {
            ApplyHighlight(hit.collider.gameObject, _toolColor);
            return;
        }

        // → Check for grabbable
        if (hit.collider.HasTag(TagType.Grabbable))
        {
            ApplyHighlight(hit.collider.gameObject, _grabbableColor);
            return;
        }

        // Phase D: Check for building
        // var building = hit.collider.GetComponentInParent<BuildingObject>();
        // if (building != null && !building.IsGhost)
        // {
        //     ApplyHighlight(hit.collider.gameObject, _buildingColor);
        //     return;
        // }
    }

    void ApplyHighlight(GameObject target, Color color)
    {
        // → Get or add HighlightEffect
        HighlightEffect effect = target.GetComponent<HighlightEffect>();
        if (effect == null)
            effect = target.AddComponent<HighlightEffect>();

        // → Configure effect
        effect.effectGroup = TargetOptions.Children;
        effect.outline = 1f;
        effect.outlineColor = color;
        effect.outlineWidth = _outlineWidth;
        effect.outlineQuality = QualityLevel.High;
        effect.glow = _glowIntensity;
        effect.glowHQColor = color;
        effect.glowWidth = 0.4f;
        effect.constantWidth = true;

        // → Turn on
        effect.highlighted = true;

        currentHighlight = effect;
        currentTarget = target;
    }
}
```

### 14.4 What Was Removed vs What Highlight Plus Handles

| Old System (FresnelHighlighter) | Highlight Plus Replacement |
|---|---|
| Custom "Highlighted" layer (slot 31) | **Not needed** — no layer swapping at all |
| Shader Graph `Highlight_Fresnel_Additive` | **Not needed** — Highlight Plus has its own shaders |
| Material `M_Highlight_Fresnel` | **Not needed** — effect generates materials internally |
| URP Render Objects renderer feature | **Replaced** by Highlight Plus renderer feature (one-time setup) |
| `UtilsPhaseB.SetLayerRecursively()` per frame | **Not needed** — `effect.highlighted = true/false` |
| `MaterialPropertyBlock` for per-object color | **Not needed** — `effect.outlineColor = color` |
| 97 lines of layer-swap code | ~30 lines of Highlight Plus API calls |

### 14.5 Color Mapping (Phase B → D)

| Game Context | Old Color | Highlight Plus Setting |
|---|---|---|
| Tools, terminals | Cyan `(0.25, 0.85, 1)` | `outlineColor = cyan`, `glowHQColor = cyan` |
| Grabbable objects | Cyan `(0.25, 0.85, 1)` | Same — or use a different shade |
| Buildings (Phase D, hammer) | Cyan `(0.25, 0.85, 1)` | Same |
| Wrench enable (Phase D) | Green `(0.3, 1, 0.3)` | `outlineColor = green` |
| Wrench disable (Phase D) | Red `(1, 0.3, 0.3)` | `outlineColor = red` |

### 14.6 Profile-Based Approach (Cleaner)

Instead of setting colors in code, create **HighlightProfile** assets:

1. Create `Profile_Tool.asset` → outline=1, glow=1.5, color=cyan
2. Create `Profile_WrenchEnable.asset` → outline=1, glow=1.5, color=green
3. Create `Profile_WrenchDisable.asset` → outline=1, glow=1.5, color=red
4. In the highlighter, swap profiles:

```csharp
[SerializeField] HighlightProfile _toolProfile;
[SerializeField] HighlightProfile _wrenchEnableProfile;
[SerializeField] HighlightProfile _wrenchDisableProfile;

void ApplyHighlight(GameObject target, HighlightProfile profile)
{
    HighlightEffect effect = target.GetComponent<HighlightEffect>();
    if (effect == null)
        effect = target.AddComponent<HighlightEffect>();

    effect.ProfileLoad(profile);
    effect.highlighted = true;
    currentHighlight = effect;
}
```

### 14.7 Bonus: See-Through for Occluded Objects

Something the old fresnel system **couldn't do at all** — Highlight Plus can show objects behind walls:

```csharp
effect.seeThrough = SeeThroughMode.WhenHighlighted;
effect.seeThroughIntensity = 0.5f;
effect.seeThroughTintColor = new Color(0, 0.5f, 1f, 0.5f);
```

Add `HighlightSeeThroughOccluder` to wall objects, and highlighted objects become visible through them — useful for tools behind crates, ores behind rocks, etc.

## 1. What Is Mesh Animator?

Mesh Animator is a **mesh-swapping animation system** designed for rendering **hundreds or thousands** of animated characters with minimal CPU and GPU cost. Instead of using Unity's skinned mesh rendering (SkinnedMeshRenderer + Animator), it **pre-bakes** all animation frames into mesh snapshots or shader textures, then swaps between them at runtime.

Think of it like a **sprite sheet, but for 3D meshes** — each "frame" is a complete mesh with vertices already in their final positions.

---

## 2. Why Not Use Unity's Animator?

| Feature | Unity Animator | Mesh Animator |
|---|---|---|
| **CPU cost per character** | High (skeletal calculations) | Very low (just swap mesh) |
| **GPU instancing** | Not possible with SkinnedMesh | Fully supported |
| **1000+ characters** | Unplayable (<5 FPS) | Smooth (60+ FPS) |
| **Animation blending** | Full blend trees | Simple crossfade only |
| **IK / Ragdoll** | Supported | Not supported |
| **Memory usage** | Low (one mesh + bones) | Higher (mesh per frame) |

**Use Mesh Animator when:**
- You need massive crowds (NPCs, zombies, soldiers, animals)
- Characters don't need complex blend trees or IK
- Performance is critical (mobile, VR, large battles)

**Don't use it when:**
- You need smooth animation blending
- Characters need IK (foot placement, hand reaching)
- You need ragdoll physics
- Only a few characters on screen

---

## 3. How It Works (The Big Idea)

```
BAKE TIME (Editor):
  Animator + SkinnedMeshRenderer
      ↓
  For each animation clip, sample every frame
      ↓
  Save each frame as a mesh snapshot (vertices, normals, tangents)
      ↓
  Store as MeshAnimation asset (ScriptableObject)

RUNTIME (Game):
  MeshAnimator component
      ↓
  Each frame: swap MeshFilter.mesh to the pre-baked frame
      ↓
  GPU draws a regular MeshRenderer (not Skinned!)
      ↓
  GPU instancing works → massive batching → amazing performance
```

Key insight: **MeshRenderer is way cheaper than SkinnedMeshRenderer** because there's no bone deformation on the GPU. And since all instances share the same mesh data, GPU instancing kicks in.

---

## 4. Two Modes: Snapshot vs Shader

### 4.1 Snapshot Mode

- **How:** Pre-bakes mesh data (vertices/normals) into memory. At runtime, swaps the mesh each frame.
- **Pro:** Simple, works everywhere, supports all shaders
- **Con:** Uses more memory (one mesh per frame per animation)
- **Best for:** Small to medium crowds, mobile

### 4.2 Shader Mode

- **How:** Bakes animation data into textures. A custom shader reads the texture to deform vertices on the GPU.
- **Pro:** Extremely fast, very low memory, perfect GPU instancing
- **Con:** Requires special shaders (provided), can't use custom material shaders without modification
- **Best for:** Massive crowds (1000+), when you control the shader

### Key Classes

| Mode | Animation Asset | Animator Component |
|---|---|---|
| Snapshot | `SnapshotMeshAnimation` | `SnapshotMeshAnimator` |
| Shader | `ShaderMeshAnimation` | `ShaderMeshAnimator` |

Both inherit from `MeshAnimationBase` / `MeshAnimatorBase`.

## 6. Baking Animations

|---|---|---|

| 500–2000 | 10–15 | Memory is priority |

## 7. Scene Setup — Step by Step

### 7.1 Basic: One Animated Character

1. **Create empty GameObject** in scene → name it "Crowd_Unit"
2. Add components:
   - `MeshFilter` (auto-added by MeshAnimator)
   - `MeshRenderer` → assign your character material
   - `SnapshotMeshAnimator` (or `ShaderMeshAnimator`)
3. On the MeshAnimator:
   - `baseMesh` → drag the baked base mesh
   - `defaultAnimation` → drag the idle MeshAnimation asset
   - `animations` → add all baked MeshAnimation assets
4. Press Play → character animates!

### 7.2 Spawning a Crowd

```csharp
using FSG.MeshAnimator;

public class CrowdSpawner : MonoBehaviour
{
    [SerializeField] GameObject crowdUnitPrefab;
    [SerializeField] int count = 500;
    [SerializeField] float spawnRadius = 50f;
    
    void Start()
    {
        for (int i = 0; i < count; i++)
        {
            Vector3 pos = Random.insideUnitSphere * spawnRadius;
            pos.y = 0;
            GameObject unit = Instantiate(crowdUnitPrefab, pos, Quaternion.identity);
            
            var animator = unit.GetComponent<MeshAnimatorBase>();
            animator.Play("Walk");
            animator.speed = Random.Range(0.8f, 1.2f);
        }
    }
}
```

### 7.3 Shader Mode Setup

1. Bake with **Shader** mode selected
2. On the character material, use one of the provided shaders:
   - `MeshAnimator/Standard` (Built-in)
   - `MeshAnimator/URP/Lit` (URP)
   - Use ShaderGraph variants from `ShaderGraph/` folder
3. The shader reads a **texture** containing vertex positions
4. Assign the baked texture to the material

Concrete implementation for Snapshot mode. Swaps mesh data every frame.

Concrete implementation for Shader mode. Updates shader texture indices.

ScriptableObject that holds baked animation data.

Singleton that **manages all MeshAnimator update ticks** centrally.

## 10. LOD System

Mesh Animator has a built-in LOD system that **reduces animation FPS based on distance** from the camera.

### 10.1 Setting Up LOD

On the MeshAnimator Inspector, expand `LOD Levels` and add entries:

| LOD Level | FPS | Distance |
|---|---|---|
| Level 0 | 15 | 20 |
| Level 1 | 8 | 50 |
| Level 2 | 4 | 100 |

**Meaning:**
- Objects closer than 20 units → full FPS (30 from the `FPS` property)
- Objects 20–50 units away → 15 FPS
- Objects 50–100 units away → 8 FPS
- Objects 100+ units away → 4 FPS

### 10.2 LOD Camera

- `LODCamera` field specifies which camera to measure distance from
- If null, automatically uses the first camera found
- For VR, set this to the HMD camera

### 10.3 Why LOD Matters

At distance, the player can't tell if a character updates at 30fps or 8fps. This **massively** reduces CPU work for distant crowds.

## 11. Exposed Transforms

Exposed Transforms let you **track the position of specific bones** even though there's no skeleton at runtime.

### 11.1 Use Cases

- Attach a weapon to a hand bone
- Place a health bar above the head bone
- Emit particles from a foot bone

### 11.2 How To Set Up

1. In the Baker, specify **Exposed Transforms** (bone names to track)
2. Bake as normal — the baker records transform matrices per frame
3. At runtime, create **child GameObjects** with matching names
4. The MeshAnimator automatically moves these child transforms to match the baked bone position

### 11.3 Example

```
BakedCharacter (MeshAnimator)
├── RightHand       ← child named same as exposed bone
│   └── Sword       ← your weapon model
├── Head            ← another exposed bone
│   └── HealthBar
```

The `RightHand` child will automatically move to where the right hand bone was during baking.

### 12.2 Setup

2. On the MeshAnimation asset, set `rootMotionMode = AppliedToTransform`

## 14. Crossfading

Crossfading smoothly blends between two animations over a short duration.

### 14.1 How It Works

1. When crossfade starts, it creates an intermediate mesh that interpolates between the ending pose of animation A and the starting pose of animation B
2. Over `speed` seconds, the blend factor goes from 0→1
3. Uses exposed transform interpolation if available

### 14.2 Pool Preallocation

Crossfading allocates temporary meshes. To avoid GC spikes:

```csharp
animator.PrepopulateCrossfadePool(3); // pre-allocate 3 crossfade meshes
```

## 15. MeshAnimatorManager

The `MeshAnimatorManager` is a **centralized update loop** for all MeshAnimators in the scene.

### 15.1 How It Works

- Auto-creates as a singleton
- All MeshAnimators call `MeshAnimatorManager.AddAnimator(this)` on enable
- All MeshAnimators call `MeshAnimatorManager.RemoveAnimator(this)` on disable
- Manager calls `UpdateTick(Time.time)` on each registered animator

### 15.2 Why Centralized?

Having 1000 individual `Update()` calls is expensive. A single manager iterating an array is much faster.

### 15.3 You Don't Need To Do Anything

This is automatic. The manager creates itself, and animators register/unregister themselves.

## 16. Performance Tips

### 16.1 General Tips

1. **Use Shader mode** for maximum performance (1000+ characters)
2. **Enable GPU instancing** on materials
3. **Use LOD levels** — 4 FPS at distance is indistinguishable from 30 FPS
4. **Lower baked FPS** for non-hero characters (15 FPS is usually fine)
5. **Use `Frame Skip`** in the baker to reduce memory
6. **Disable `updateWhenOffscreen`** (default) — offscreen characters don't animate
7. **Pre-populate crossfade pool** if crossfading frequently
8. **Share materials** — all instances using the same material = one draw call (with instancing)

### 16.2 Memory Guidelines

| Characters | Animations | Baked FPS | Approx Memory |
|---|---|---|---|
| 100 | 5 clips | 30 | ~50–100 MB |
| 500 | 5 clips | 15 | ~100–200 MB |
| 2000 | 3 clips | 10 | ~200–400 MB |

Memory depends heavily on mesh vertex count. Reduce vertex count for crowd models.

### 16.3 Comparison

| Scenario | Animator (CPU) | MeshAnimator Snapshot (CPU) | MeshAnimator Shader (CPU) |
|---|---|---|---|
| 100 units | ~5ms | ~0.5ms | ~0.1ms |
| 500 units | ~25ms | ~2ms | ~0.3ms |
| 2000 units | Unplayable | ~8ms | ~1ms |

## 18. Troubleshooting

| Problem | Fix |
|---|---|
| Character doesn't animate | Check `playAutomatically` is true, `defaultAnimation` is assigned |
| T-pose / frozen | Animation assets not assigned in `animations` array |
| Mesh flickering | Check `skipLastLoopFrame` for looping anims |
| Memory too high | Lower baked FPS, use Frame Skip, reduce vertex count |
| No GPU instancing | Ensure material has GPU instancing enabled, use same material for all |
| Exposed transforms wrong position | Child names must exactly match baked bone names |
| Animation events not firing | Set `eventReciever` to the correct GameObject |
| Crossfade stutters | Pre-populate crossfade pool |
| LOD not working | Set `LODCamera` or ensure at least one Camera exists |
| Shader mode artifacts | Use provided MeshAnimator shaders, not custom ones |

## 1. What Is Text Animator?

Text Animator adds **per-character animation effects** to TextMeshPro text. Characters can shake, wave, bounce, rotate, fade, change color — all controlled through **rich text-style tags** directly in your text string.

It also includes a **typewriter system** (characters appear one at a time, like in RPG dialogue boxes).

```
"<shake>DANGER!</shake> The <wave>ocean</wave> is <bounce>rising</bounce>!"
```

Each word animates independently with its tagged effect.

|---|---|
| **Dialogue system** | Typewriter text with character-by-character reveal |
| **UI emphasis** | Shaking "WARNING" text, waving quest titles |
| **Damage numbers** | Bouncing, scaling numbers that appear and fade |
| **Tutorial text** | Important words highlighted with effects |
| **Narrative games** | Emotional text with wobble, color shifts |
| **Mobile UI** | Attention-grabbing animated labels |

## 4. Core Concepts

### 4.1 The Architecture

```
TextMeshPro (or TextMeshProUGUI)
    ↓ reads text, generates mesh
TextAnimator component
    ↓ intercepts mesh data
    ↓ applies per-character vertex modifications (position, color, rotation)
    ↓ writes modified mesh back
TextAnimatorPlayer (optional)
    ↓ controls typewriter reveal (one character at a time)
```

### 4.2 Two Types of Effects

| Type | Tag Format | When It Applies | Example |
|---|---|---|---|
| **Behavior** | `<tag>text</tag>` | Continuously animates (loops forever) | `<shake>`, `<wave>`, `<wiggle>` |
| **Appearance** | `<tag>text</tag>` | Plays once when character appears (typewriter) | `<size>`, `<fade>`, `<offset>` |

- **Behavior effects** are visible all the time — characters keep moving
- **Appearance effects** only play during the typewriter reveal, then stop

### 4.3 How Tags Work

Tags are embedded directly in your TMP text string:

```
"Normal text <shake>shaking text</shake> normal again"
```

- Tags are **not** rendered — they're parsed and removed
- Tags can be **nested**: `<shake><wave>both effects</wave></shake>`
- Tags can have **modifiers**: `<shake a=5 f=2>` (amplitude=5, frequency=2)

## 5. Built-in Effects (Rich Text Tags)

### 5.1 Behavior Effects (Continuous Animation)

These effects loop forever once the text is visible:

| Tag | Effect | Description |
|---|---|---|
| `<shake>` | Shake | Characters jitter randomly in position |
| `<rot>` | Rotate | Characters continuously rotate |
| `<wiggle>` | Wiggle | Characters wiggle side to side |
| `<wave>` | Wave | Characters move in a sine wave pattern |
| `<swing>` | Swing | Characters swing like a pendulum |
| `<incr>` | Increase | Characters scale up and down rhythmically |
| `<slide>` | Slide | Characters slide horizontally |
| `<bounce>` | Bounce | Characters bounce up and down |
| `<fade>` | Fade | Characters fade in and out |
| `<rainb>` | Rainbow | Characters cycle through rainbow colors |
| `<dangle>` | Dangle | Characters dangle as if hanging |
| `<pend>` | Pendulum | Characters swing in pendulum motion |

### 5.2 Appearance Effects (One-Time on Reveal)

These play **once** when the typewriter reveals each character:

| Tag | Effect | Description |
|---|---|---|
| `<size>` | Size | Characters scale from 0 to full size |
| `<fade>` | Fade | Characters fade from transparent to opaque |
| `<offset>` | Offset | Characters slide in from an offset position |
| `<rdir>` | Random Direction | Characters fly in from random directions |
| `<vertexp>` | Vertical Expand | Characters expand vertically from a line |
| `<horiexp>` | Horizontal Expand | Characters expand horizontally from center |
| `<diagexp>` | Diagonal Expand | Characters expand diagonally |
| `<rot>` | Rotate | Characters rotate in as they appear |

### 5.3 Tag Modifiers

Most tags accept parameter modifiers:


Common modifiers:
- `a` = amplitude (how much the effect moves)
- `f` = frequency (how fast the effect cycles)
- `d` = delay between characters

Example usage:

```

"<shake a=20>AGGRESSIVE SHAKE</shake>"
"<bounce f=3>Fast bounce</bounce>"
```

## 7. The Typewriter (TextAnimatorPlayer)

### 7.1 What It Does

The typewriter reveals characters one at a time, with configurable timing. It interacts with TextAnimator to play **appearance effects** as each character appears.

### 7.2 Key Properties

| Property | Type | Default | Purpose |
|---|---|---|---|
| `useTypeWriter` | bool | true | Enable/disable typewriter |
| `waitForNormalChars` | float | 0.03 | Wait time per normal character (seconds) |
| `waitLong` | float | 0.6 | Wait time for `.`, `!`, `?` |
| `waitMiddle` | float | 0.2 | Wait time for `,`, `;`, `:`, `)`, `-` |
| `avoidMultiplePunctuactionWait` | bool | false | Only last punctuation in a sequence waits |
| `waitForNewLines` | bool | true | Pause at newlines |
| `waitForLastCharacter` | bool | true | Wait for the final character |
| `canSkipTypewriter` | bool | true | Allow skipping |
| `hideAppearancesOnSkip` | bool | false | Skip appearance animations on skip |
| `triggerEventsOnSkip` | bool | false | Fire all remaining events on skip |
| `disappearanceOrientation` | enum | SameAsTypewriter | Direction text disappears |

### 7.3 Start Modes

The typewriter can auto-start from:

| Mode | When It Starts |
|---|---|
| `FromScriptOnly` | Only when you call `StartShowingText()` |
| `OnEnable` | Every time the GameObject enables |
| `OnShowText` | When `ShowText()` is called |
| `AutomaticallyFromAllEvents` | Both OnEnable and OnShowText |

### 7.4 Events

| Event | When |
|---|---|
| `onTextShowed` | All text finished showing |
| `onTypewriterStart` | Typewriter begins |
| `onCharacterVisible` | Each character becomes visible (CharacterEvent with char) |

### 7.5 Custom Player (Subclassing)

You can create custom typewriters by inheriting `TAnimPlayerBase`:

```csharp
using Febucci.UI.Core;

public class MyCustomPlayer : TAnimPlayerBase
{
    protected override float GetWaitAppearanceTimeOf(char character)
    {
        // Return custom wait time per character
        return 0.05f;
    }
    
    protected override float GetWaitDisappearanceTimeOf(char character)
    {
        return 0.02f;
    }
    
    protected override IEnumerator WaitInput()
    {
        // Custom input waiting (for dialogue systems)
        while (!Input.GetKeyDown(KeyCode.Space))
            yield return null;
    }
}
```

## 10. Action Tags (Special Commands)

Action tags are **inline commands** that execute during the typewriter reveal:

### 10.1 Built-in Action Tags

| Tag | Purpose | Example |
|---|---|---|
| `{waitinput}` | Pause typewriter until player presses input | `"Press any key{waitinput} to continue"` |
| `{speed=X}` | Change typewriter speed | `"Normal speed {speed=0.5}now slower"` |
| `{pause=X}` | Pause for X seconds | `"Wait for it...{pause=2}BOOM!"` |

### 10.2 Custom Action Tags

You can create custom TypewriterActions:

```csharp
public class PlaySoundAction : TypewriterAction
{
    public override void OnAction(string parameter)
    {
        // parameter is the text after "=" in the tag
        AudioManager.PlaySound(parameter);
    }
}
```

Usage: `"The door {sfx=door_creak}creaks open"`

## 11. Integration with Other Systems

### 11.1 Dialogue Systems

Text Animator works great with dialogue systems. Common pattern:

```csharp
public class DialogueManager : MonoBehaviour
{
    [SerializeField] TextAnimatorPlayer player;
    [SerializeField] TextAnimator textAnimator;
    
    string[] dialogueLines;
    int currentLine = 0;
    
    public void StartDialogue(string[] lines)
    {
        dialogueLines = lines;
        currentLine = 0;
        ShowCurrentLine();
    }
    
    void ShowCurrentLine()
    {
        string line = dialogueLines[currentLine];
        textAnimator.SetText(line);
        player.ShowText(line);
        player.onTextShowed.AddListener(OnLineComplete);
    }
    
    void OnLineComplete()
    {
        player.onTextShowed.RemoveListener(OnLineComplete);
        // Wait for input, then advance
    }
    
    public void AdvanceDialogue()
    {
        if (!textAnimator.allLettersShown)
        {
            player.SkipTypewriter(); // Skip if still typing
        }
        else
        {
            currentLine++;
            if (currentLine < dialogueLines.Length)
                ShowCurrentLine();
        }
    }
}
```

The package includes integration packages for:
- **PlayMaker** — Visual scripting actions
- **Visual Scripting** — Unity Visual Scripting nodes

Found in `Integrations/` folder as `.unitypackage` files.

## 13. Performance Tips

1. **Disable effects on hidden text** — TextAnimator still processes invisible text
2. **Use simpler effects** for large amounts of text (shake, fade are cheapest)
3. **Limit simultaneous animated characters** — 500+ animated characters can impact mobile
4. **Reuse TextAnimator objects** — don't create/destroy for each dialogue line
5. **Pool damage number objects** instead of instantiating
6. **Behavior effects are continuous** — they run every frame; use sparingly in large quantities

## 14. Troubleshooting

| Problem | Fix |
|---|---|
| Tags show as raw text | Ensure `TextAnimator` component is on the same GameObject as TMP |
| No typewriter effect | Add `TextAnimatorPlayer` component |
| Characters don't animate | Check that TMP text contains valid tags (e.g., `<shake>text</shake>`) |
| Typewriter too fast/slow | Adjust `waitForNormalChars` on TextAnimatorPlayer |
| Text doesn't appear | Check `startTypewriterMode` — may need to call `ShowText()` manually |
| Missing effects | Check tag spelling: `<shake>` not `<Shake>` (case sensitive) |
| Custom effects not working | Register custom effect tag in global data or component |
| "TMP not found" errors | Import TextMeshPro via Package Manager |
| Text layout breaks | TextAnimator modifies vertices — complex layouts may need adjustment |
| Disappearance not working | Set `useTypeWriter = true` and call `StartDisappearingText()` |
